Admin

Admin API reference

Bearer-token API for scripted writes. Skip the deploy pipeline when you just need to push data.
🔑 Manage keys

Authentication

Every call needs a mbak_… bearer token. Mint one at /admin/api-keys (label + TTL), copy it once, store it in your script's secret manager.

Authorization: Bearer mbak_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx

Or use X-API-Key: mbak_… if your client can't set Authorization.

Verify your key works

curl -fsS https://workshopmods.org/api/admin/whoami \
  -H "Authorization: Bearer $MODBOARD_KEY"

Returns the key's label, prefix, created/expires timestamps.

Mods

List all tracked mods

GET  /api/admin/mods
curl -fsS https://workshopmods.org/api/admin/mods \
  -H "Authorization: Bearer $MODBOARD_KEY" | jq

Get one mod

GET  /api/admin/mods/{workshop_id}

Add a mod

POST /api/admin/mods
Content-Type: application/json

{"workshop_id": 3724689682, "name": "DayCount", "public": true}
curl -fsS https://workshopmods.org/api/admin/mods \
  -H "Authorization: Bearer $MODBOARD_KEY" \
  -H "Content-Type: application/json" \
  -d '{"workshop_id": 3724689682, "name": "DayCount"}'

Optional fields: workshop_url (auto-built from id if omitted), github_url, public (default true).

Bulk-add mods (≤200 per call)

POST /api/admin/mods/bulk
Content-Type: application/json

{
  "items": [
    {"workshop_id": 1, "name": "ModA"},
    {"workshop_id": 2, "name": "ModB"}
  ]
}

Returns a per-item outcome: created / exists / bad_input.

Update a mod (partial)

PATCH /api/admin/mods/{workshop_id}
Content-Type: application/json

{"title": "New title", "public": false}

Allowed fields: name, title, workshop_url, github_url, thumbnail_url, public.

Delete a mod

DELETE /api/admin/mods/{workshop_id}

Cascades to snapshots, comments, changelogs, discussions, roadmap, subscriptions — and, for manual mods, uploaded file versions (DB rows; on-disk files are left to be reclaimed, delete versions explicitly first if you need them gone).

Manual (non-Steam) mods & file hosting

For mods that don't live on Steam Workshop. ModBoard hosts the files itself, with multiple versions per mod. Everything below is doable via API key — no UI needed.

Create a manual mod

POST /api/admin/mods/manual
Content-Type: application/json

{
  "name": "MyCustomMod",
  "title": "My Custom Mod",
  "game_name": "Minecraft",
  "description": "What it does.",
  "public": true
}
curl -fsS https://workshopmods.org/api/admin/mods/manual \
  -H "Authorization: Bearer $MODBOARD_KEY" \
  -H "Content-Type: application/json" \
  -d '{"name":"MyCustomMod","game_name":"Minecraft"}'

Returns the created mod, including its assigned id (a small integer from a dedicated sequence — never collides with Steam workshop ids) and source: "manual". Use that id for the file calls below. Optional: title, description, game_name, github_url, public (default true).

List a mod's file versions

GET  /api/admin/mods/{mod_id}/files

Returns every version (newest first) with id, version, filename, size_bytes, sha256, download_count, and is_current.

Upload a file version (multipart)

POST /api/admin/mods/{mod_id}/files
Content-Type: multipart/form-data

fields: version (required), upload (file, required), changelog (optional)
curl -fsS https://workshopmods.org/api/admin/mods/42/files \
  -H "Authorization: Bearer $MODBOARD_KEY" \
  -F "version=1.0.2" \
  -F "changelog=Fixed the thing" \
  -F "upload=@./MyCustomMod-1.0.2.zip"

The new upload automatically becomes the current download (the previous current is demoted). Files stream to disk; uploads over the server's MAX_UPLOAD_MB cap (default 500 MB) return 413. Returns the created file record.

Set a version as current

POST /api/admin/mods/files/{file_id}/set-current

Points the main Download button at this version.

Delete a file version

DELETE /api/admin/mods/files/{file_id}

Removes the DB row and the stored file from disk. Returns 204.

Public download URLs (no key needed)

GET /mod/{mod_id}/download            # current version
GET /mod/{mod_id}/download/{file_id}  # a specific version

Served as an attachment. View + download counts are tracked per IP.

Steam poll trigger

POST /api/admin/poll

Queues a Steam scrape cycle. Returns immediately (202) with {"status": "queued"} or {"status": "already_running"}. Coalesces concurrent calls so you can't accidentally spawn 10 scrapers.

News posts

List

GET  /api/admin/news

Create

POST /api/admin/news
Content-Type: application/json

{
  "title": "ModBoard is live",
  "body": "Welcome! **Bold** and *italic* supported. > quote",
  "kind": "celebration",
  "show_banner": true
}

Allowed kind: info, update, warning, celebration. show_banner=true makes the latest active+banner post pop as a site-wide strip.

Update / delete

PATCH  /api/admin/news/{id}
DELETE /api/admin/news/{id}

Roadmap (per-mod)

List items for a mod

GET  /api/admin/roadmap/{mod_id}

Create item

POST /api/admin/roadmap
Content-Type: application/json

{
  "mod_id": 3724689682,
  "title": "Add settings panel",
  "body": "User-tweakable counter limits.",
  "status": "in_progress",
  "position": 1
}

Allowed status: planned, in_progress, done, cancelled. Lower position appears first.

Update / delete

PATCH  /api/admin/roadmap/{item_id}
DELETE /api/admin/roadmap/{item_id}

Error format

All non-2xx responses follow:

{"detail": "human-readable reason"}
  • 401 — missing/invalid/expired/revoked key
  • 400 — bad input (wrong type, unknown field, enum violation)
  • 404 — target not found
  • 409 — already exists (mod with that workshop_id)
  • 413 — uploaded file exceeds the server size cap

n8n / curl example: import a CSV of mods

#!/usr/bin/env bash
set -euo pipefail
KEY="$MODBOARD_KEY"

# items.csv has lines like:  3724689682,DayCount
mapfile -t lines < items.csv
items='[]'
for line in "${lines[@]}"; do
  id="${line%%,*}"; name="${line#*,}"
  items=$(echo "$items" | jq --argjson id "$id" --arg n "$name" \
    '. += [{"workshop_id":$id,"name":$n}]')
done

curl -fsS https://workshopmods.org/api/admin/mods/bulk \
  -H "Authorization: Bearer $KEY" \
  -H "Content-Type: application/json" \
  -d "{\"items\":$items}" | jq

Key hygiene

  • Keys are sha256-hashed at rest. Losing the plain key = revoke + re-issue.
  • Default TTL is 24h. Pick the shortest window that fits your workflow.
  • Revoke immediately if a key leaks (committed to a repo, posted in chat, etc.).
  • One key per use-case — separate "n8n-prod", "local-import", "github-action" so revocation is surgical.
  • Every API write goes through the same CSRF-exempt path but is logged in security_events via the key's last_used_at.
